# AGENTS.md — the policy

The one instruction file for this repository; `CLAUDE.md` imports it.
`README.md` is setup and the everyday commands. `docs/status.md` is what is
unfinished, and `docs/plans/` holds the plans.

## What this repository is

**Public, and the whole website.** GitHub Pages serves this tree as-is at
rux-sm.github.io: `/` is `index.html` here, and every folder named like a
URL path is that app — `design/` at `/design/`, `scheduler/` at
`/scheduler/`, `notes/` at `/notes/`. **A push to `main`
publishes**, after CI runs the check. There is no release, no tag and no
separate publish step.

One thing stays outside it, for privacy, cloned beside it: `rux-ln-atlas`,
the LN knowledge library the Notes pages are rendered from. A task that
needs it edits it in the same session, after reading its own `AGENTS.md`.

**The database has no repository.** It is the one Supabase project,
`udnmqhayzhrbltxzzhjw`, named `rux-ui` in the dashboard after the old trips
app, which still writes its `public` tables. A change to it is SQL shown to
rux and applied on a yes through the Supabase connection, as a named
migration the project lists; sign-in settings are changed in the dashboard.
No migration file and no database configuration is committed here. The
`rux-backend` repository that held them was archived on 2026-09-13, private,
with the identity plan and the schema snapshot.

## One session

A task edits every folder it touches in one session. No memo, no request to
another folder, no second authorization for the same task. What does not
relax: atlas content leaves atlas only through `npm run export`; Design is
authored with invented, generic content, and nothing from atlas or a client
goes under `design/`; a database change is applied to production as its own
deliberate step, never by a website deploy.

## The four commands

    npm run serve               the site at http://localhost:8640/, loopback only
    npm run serve -- --private  atlas's internal tier, rendered and served on :8644, never published
    npm run build               regenerate what is committed but derived
    npm run check               every app through the shared check, Notes' gates, the names sweep
    npm run check -- --full     the same plus Design's own verify; what CI runs
    npm run export              atlas's export tier into notes/data/guides/, rebuilt and checked

Publishing is `git push`. The pre-commit hook sweeps the staged bytes of
every text file for names before the commit exists, then runs the fast
check; arm it once per clone: `git config core.hooksPath .githooks`.

## What must not be invented

Every `rux--*` class comes from `design/css/rux.css`, compiled from Carbon;
the check fails on one that does not. A class or rule an app needs is added
to Design with invented content, never as a local rule on a `rux--*` class.
A colour goes in the app's `rux-theme.css` inside a `[data-theme]` block; a
component rule in its `rux-overrides.css` at Carbon's specificity; a
component Carbon lacks is the app's own, under its own prefix, every colour
a `--rux-*` token. No Carbon file is ever edited.

## Documents

Git history is the record. A commit message says what changed and why; a
document says only what is true now.

**Six kinds, each with one place.** A how-to answers "how do I do this?" A
reference answers "what is true about this?"

| Kind | Where it lives | What it is for |
| :--- | :--- | :--- |
| readme | `README.md` at the root and in each app folder | what this is, and how to run and check it |
| rules | this `AGENTS.md`, which `CLAUDE.md` imports | the rules, each with one line of reason |
| status | `docs/status.md` | open work |
| how-to | the owning folder's `docs/` | the steps to perform a task |
| reference | the owning folder's `docs/` | a contract, spec or inventory to look up |
| plan | `docs/plans/` | a change being decided or built |

Readme, rules and status files, and a skill's `SKILL.md`, are known by their
names. Every other document opens with a `type:` header line naming its kind.

**`tools/check-docs.mjs` checks these, as part of `npm run check`:**

- Every document says its kind, and a plan lives only in `docs/plans/`.
- Every document is reachable by following links and file names from the root
  `README.md`. A folder named covers the files directly in it.
- Every file a document names exists. Plans are skipped, because they name
  files that do not exist yet. A name only atlas could hold is checked when
  atlas sits beside this repository, and the check says when it could not look.
- A README fails over 150 lines. Any other document warns over 300.
- A status item is one bullet of at most three lines.
- A plan has four parts: `## Goal`, `## Decisions`, `## Questions` and
  `## Tasks`. A ticked box or a plan with no tasks fails, because finished work
  is deleted. A plan untouched for 30 days warns.
- A phrase that records history, like "corrected on" or "until 2026-", warns.

**Plans.** Work that spans more than one session gets a plan first, and rux
answers its questions and says go before building starts. A plan changes like
any document: decisions get corrected, found work gets added, and answered
questions and finished tasks get deleted. It never records when something was
done, and it is deleted with its last task. Site work is planned here even when
it touches atlas; atlas-only work is planned in atlas. The status list does not
name plans, because the plans folder is the list.

**Principles no check can prove:**

- **One home per fact.** Other documents link to it and never restate it.
- **A reason is one sentence.** The argument, measurements and rejected
  options go in the commit message.
- **A correction replaces the wrong sentence.** It never adds a note beside it.
- **Code and its document change in the same commit.**
- **Names people choose are lowercase.** A name a tool or a convention fixes
  keeps its spelling: `README.md`, `AGENTS.md`, `CLAUDE.md`, `LICENSE`,
  `NOTICE`, `SKILL.md`, `ORDER` and `PIN`.
- **No other kind.** No logs, audits, memos or decision records.
- **Comments too.** A code comment says what the code does and why, in the
  present tense.

## Commits

`type(scope): Subject`, imperative, authored by rux alone with no AI
attribution. No hook checks the typography any more; the pre-commit hook
checks what matters.
