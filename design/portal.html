The registry

What each gate catches, and what it is blind to. Read from tools/lib/gates.mjs.

Kind
Runs
Catches
Blind to
build-namespace node in verify `cds` leakage into output anything visual
build-portal-icons node in verify a `#i-name` emitted into portal.html that the committed sprite has no `<symbol>` for every page it does not generate — its unit is portal.html alone
check-classes node in verify a class used in HTML or `js/` with no CSS behind it · a class whose component was stripped a class that resolves but renders wrong
check-tokens node in verify a `var(--rux-*)` that resolves to nothing a token whose *value* moved. check-token-values covers the values DECLARED in css/rux.css and only those: not a value that moves through the cascade, not one declared in css/rux-theme.css or css/rux-overrides.css, and not what a browser finally computes
check-token-values node in verify a --rux-* value that moved, was added or was dropped, under a stable name a value that changes only through the CASCADE — this reads what css/rux.css declares, not what a browser computes. Also anything in css/rux-theme.css: that file is the project's own and is meant to move
check-icons node in verify a `<use>` pointing at a symbol the sprite does not carry · a fragment referencing the sprite externally or a template referencing it bare · a sprite out of step with `build-icons.mjs` which glyph a `<use>` points at — half of that is now check-glyphs, the other half (is this the right glyph for this SLOT) is still nobody's
check-glyphs node in verify a sprite symbol that does not DRAW the glyph its name claims — a hand-edited path, a rename without the drawing following, a glyph pasted from the wrong size, an optimiser that moved a coordinate · a symbol name @carbon/icons has no file for WHICH slot a glyph belongs in, which is the half that has actually shipped defects · anything about a glyph nothing in the sprite claims
check-slots node in verify the WRONG GLYPH in a slot — the half of the icon question every one of this project's four shipped icon defects was, and which check-icons and check-glyphs both pass 4 slots have no Carbon capture that can answer and are reported UNCOVERED rather than passed · 25 more are captured and recorded but under the corroboration bar, each resting on a single story · a slot Carbon fills from a prop, where there is no right answer · size, position and visibility
check-co-classes node in verify a modifier used without the base class that styles it a base class Carbon never pairs
check-compound node in verify two classes Carbon compounds, split across elements wrong nesting order · missing wrapper
check-tags node in verify a class on a different element type than Carbon renders it on classes no story emits (81 today)
check-ancestry node in verify a wrapper Carbon renders in **every** capture, absent here a wrapper Carbon only sometimes renders
check-coverage node in verify a component exercising fewer classes than `data/coverage.json` records standing still — it ratchets, it does not set a floor
check-inventory node in verify a component Carbon ships that docs/inventory.md has no row for · a row carrying no disposition · a row Carbon no longer ships · a component src/app.scss does not list at all · a disposition the manifest contradicts · a data/inventory.json compiled from a Carbon that is not the one installed whether a disposition is RIGHT — it insists one was made, not that it was wise
check-headings node in verify a page with no heading at all · more than one `h1` · an outline that skips a level whether a heading says anything useful · heading ORDER against visual order · a heading that is visually a heading and marked up as a div
check-aria-roles node in verify a `role` on a `rux--` class that Carbon never renders that role on a role on an unclassed element · a MISSING role · whether required child roles are present · anything turning on `aria-live`, which the extractor does not record
check-provenance node in verify a fragment that does not say where its markup came from · a template that does not say what its BEHAVIOUR was verified against, with a URL and a date whether either label is true
check-blocks node in verify a BLOCK or SLOT marker that does not pair, sits above PROVENANCE, encloses a ks- class or an inline style, uses a glyph the sprite lacks, or references an id outside its own region · a slot carrying markup outside any block, or a template with no slot · a builder/blocks.json disagreeing with its sources in ANY field, in order, or by a duplicate or a missing template record, and slot records that do not rebuild the file · a docs/builder-coverage.md whose generated table has drifted, or whose eligibility notes name a fragment that is gone, is already marked, or is named twice · a builder/guide.json naming a block or slot that does not exist, suggesting the same block into one slot twice, leaving a template with no purpose line, recommending a variant value the group does not offer, or making a suggestion whose recorded layout does not match the slot WITHOUT saying what is unverified whether the marked region is the RIGHT part of the fragment, and whether an unmarked fragment SHOULD be marked — both are readings. The coverage table counts candidates; it does not rank them. AND WHETHER A SUGGESTION IS GOOD: it checks the map is consistent with the catalogue, never that the advice is sound, and a matching container is evidence about a placement and not a verdict on one — layer, siblings, the frame and the 13 hazards in composing-pages.md are all invisible to it
build-theme-creator-icons node in verify a `#i-name` emitted into theme-creator.html that the committed sprite has no `<symbol>` for every page it does not generate - its unit is theme-creator.html alone, and never the page inside its preview
build-builder-icons node in verify a `#i-name` emitted into builder.html that the committed sprite has no `<symbol>` for every page it does not generate - its unit is builder.html alone, and never the page inside its preview
check-rendered browser by hand default browser chrome · collapsed · escaped elements anything it has no rule for · a section it has nothing to measure in
check-runtime-classes browser by hand a class in the markup that no longer exists once the modules have run — what `check-coverage` counts and nobody sees anything behind an interaction (it is load-time only), and — found by its own red run on 2026-08-29 — PARTIAL stripping. It compares SETS of class names, so removing one of six elements carrying a class changes nothing it reports; only a class that leaves the page entirely is caught. The red run has to use a class that occurs exactly once, or it comes back green.
check-spacing browser by hand a box property that disagrees with what Carbon computes for the same class set, read from `data/carbon-react-spacing.json` whether the value is RIGHT — only whether it matches Carbon; a class set neither side renders
check-behaviour browser by hand a behaviour module that stops doing what its own header claims — the state a click produces, which every other gate is blind to anything landing in a microtask: focus destination, focus restoration, and the order two surfaces close in
check-a11y browser by hand dangling idrefs · composites with many tab stops · unnamed controls · roles missing required state · focusable inside aria-hidden what a screen reader announces · focus-ring contrast · whether the tab order makes sense
