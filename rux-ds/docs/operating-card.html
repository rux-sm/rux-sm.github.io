Rux Operating Card

rux-ds · rux-ln-atlas · rux-ln-notes · rux-scheduler · rux-sm.github.io · rux-backend — one card for both Macs. The per-repo index (run, edit, verify, release) is the workspace page in rux's config; this card is the loop and the setup.

⌘P to print

Every session

The loop

The two things that have gone wrong were both left-behind work: a commit on one Mac, unpushed, and a second agent in a repo already being worked. The loop closes both.

Start

  1. Open the workspace and pull all six. Fast-forward only. If a pull refuses, see the box below before doing anything else.

    code ~/Developer/rux.code-workspace
for r in rux-ds rux-ln-atlas rux-ln-notes rux-scheduler rux-sm.github.io rux-backend; do
  git -C ~/Developer/$r pull --ff-only
done

  2. Health-check only the repo you are about to touch. Read the exit code, not the output.

    cd ~/Developer/rux-ds          && npm install --ignore-scripts && npm run verify
cd ~/Developer/rux-ln-notes    && node tools/check.mjs
cd ~/Developer/rux-ln-atlas    && python3 tools/check.py
cd ~/Developer/rux-scheduler   && node tools/check.mjs
cd ~/Developer/rux-sm.github.io && node tools/check.mjs

    rux-backend has no check of this kind: pgTAP, supabase test db, Docker, and only when a migration changes.

  3. Start agents on the tree you just pulled. One agent per repo at a time. Agents do not pull; you did.

Work flows downstream, one repo at a time

Finish, commit and push the upstream repo before you sync the downstream one. The sync scripts refuse a dirty upstream, so this is the order the tools already expect.

Content atlas → notes

  1. atlas: edit · python3 tools/check.py · commit · push
  2. notes: sh tools/sync-guides.sh
  3. node tools/build.mjs · node tools/check.mjs
  4. commit · push — the push is the publication

Design system rux-ds → every module

  1. rux-ds: edit · npm run verify · commit · push
  2. a line in CHANGES.md if a class left · git tag vX.Y.Z · git push origin vX.Y.Z
  3. from rux-ds on main: sh tools/roll-out.sh vX.Y.Z
  4. each app it moved: read the drift report · commit · push

Every app moves in one pass — the hub, notes and the scheduler. An app already holding the tag's bytes is left alone, pin and all. tools/drift.mjs reports what an app still lacks after a move.

A new app rux-ds → hub

  1. sh tools/new-project.sh ~/Developer/<repo>
  2. one entry in the hub's switcher.json
  3. hub: node tools/check.mjs · commit · push
  4. add it to docs/rux.code-workspace, the index, and the loops on this card

Its own repository and folder, serving at rux-sm.github.io/<repo>/. Apps are shared by URL, the design system by pin, nothing else.

End

  1. Commit in every repo you touched. The hook checks the message: type(scope): Subject, subject ≤ 50 characters, body wrapped at 72, no AI trailer of any kind.

  2. Push every repo you touched, then confirm each one reads level with origin and lists no file. The branch line alone cannot see an uncommitted or untracked file.

    for r in rux-ds rux-ln-atlas rux-ln-notes rux-scheduler rux-sm.github.io rux-backend; do
  git -C ~/Developer/$r fetch -q; git -C ~/Developer/$r status -sb
done
## main...origin/main      ← one such line per repo and NOTHING under it;
                          a file listed there is work only this Mac has

  3. Close the lid only after the push. Nothing stays local on either Mac. Ever.

Never

  • Hand-edit vendor/ or data/guides/ in notes. The next sync erases the edit; the fix belongs upstream.
  • Edit a generated file in rux-ds: css/rux.css, css/rux.min.css, kitchen-sink.html, portal.html, the README stats table.
  • Work around a "dirty tree" or "wrong identity" refusal. It is holding a rule for you.
  • Run two agent sessions in the same repo. Different repos at once are fine.
  • Send anything from notes or atlas into rux-ds except an ask with invented content that check-publishable clears. Never a real page.

When a pull refuses

It means you committed on the other Mac and forgot to push before switching. Both sides have real commits. Put yours on top of theirs, re-check, push.

git pull --rebase origin main   # then re-run that repo's check, then: git push

A conflict in a generated file — css/rux.css, kitchen-sink.html, portal.html, the README stats table, MEASURED, guides/*.html — is never resolved by editing it. Take either side, run the generator (npm run verify, node tools/build.mjs, node tools/measure.mjs), then git add the result and git rebase --continue. The hooks do not run while a rebase replays commits, so the check you re-run afterwards is the only one.

Once per Mac

Set up — or check — the other Mac

Use this page before continuing work on another machine. If the six repositories are already there, do not clone them again: start at step 2 and continue through step 6. A clone contains the files, but not the machine-local hook setting, dependencies, Python environment or VS Code workspace.

You need: git; Node 22.13 or newer; Python 3.9 or newer; VS Code; and access to the two private repositories, rux-ln-atlas and rux-backend. In VS Code, open the Command Palette and run “Shell Command: Install 'code' command in PATH”. For a private clone, use a GitHub personal access token with repository access when git asks for a password; macOS then stores it in the keychain. Docker Desktop and the Supabase CLI are needed only to run rux-backend's migrations or tests locally — not to work in any other repo.

git --version
node --version          # 22.13 or newer
python3 --version       # 3.9 or newer
code --version

  1. Only if they are missing: clone all six into ~/Developer, under exactly these names and beside one another. That layout matters because notes reads its two sibling repositories, and because only rux-sm.github.io can carry that name — it is what publishes at the account root. If a directory already exists, stop instead of cloning over it; use the pull commands in step 2.

    mkdir -p ~/Developer && cd ~/Developer
git clone https://github.com/rux-sm/rux-ds.git
git clone https://github.com/rux-sm/rux-ln-atlas.git
git clone https://github.com/rux-sm/rux-ln-notes.git
git clone https://github.com/rux-sm/rux-scheduler.git
git clone https://github.com/rux-sm/rux-sm.github.io.git
git clone https://github.com/rux-sm/rux-backend.git

  2. Pull all six before doing any work. --ff-only refuses to hide a commit that exists only on this Mac. If it refuses, use “When a pull refuses” on page 1.

    for r in rux-ds rux-ln-atlas rux-ln-notes rux-scheduler rux-sm.github.io rux-backend; do
  git -C ~/Developer/$r pull --ff-only
done

  3. Set the commit identity, then arm the hooks. The identity is a machine setting. The hook path is a clone setting, so pulling files from GitHub does not install it. Notes deliberately uses a different path.

    git config --global user.name "rux"
git config --global user.email "rux.dev@pm.me"

git -C ~/Developer/rux-ds        config core.hooksPath .githooks
git -C ~/Developer/rux-ln-atlas  config core.hooksPath .githooks
git -C ~/Developer/rux-ln-notes  config core.hooksPath tools/githooks
git -C ~/Developer/rux-scheduler config core.hooksPath .githooks
git -C ~/Developer/rux-sm.github.io config core.hooksPath .githooks
git -C ~/Developer/rux-backend   config core.hooksPath .githooks

    Confirm the values instead of assuming. A value here is still not proof the hook runs — the setting and the hook FILE are two halves and a clone carries neither. rux-backend had no hook at all until 2026-09-04 and every commit in it went unchecked. Step 6 is what settles it.

    for r in rux-ds rux-ln-atlas rux-ln-notes rux-scheduler rux-sm.github.io rux-backend; do
  printf '%s: ' "$r"; git -C ~/Developer/$r config --get core.hooksPath
done

  4. Install and run the first check in each. You want exit 0 from verify, check: clean from atlas, and gates passed from notes with no NAMES WERE NOT CHECKED line above it. Three things look like failures and are not: npm warns that it skipped install scripts (expected; read the exit line), an atlas warning names a content defect (the text-cache warning clears once the venv line has run; the venv is per machine and gitignored), and notes prints where the sibling checkouts stand under “siblings (live)”, which is information and never a failure. Commit nothing during setup.

    cd ~/Developer/rux-ds          && npm ci --ignore-scripts && npm run verify; echo "exit $?"
cd ~/Developer/rux-ln-atlas    && python3 tools/build.py && python3 tools/check.py
cd ~/Developer/rux-ln-atlas    && python3 -m venv .venv && .venv/bin/python -m pip install -q pypdf && .venv/bin/python tools/text.py
cd ~/Developer/rux-ln-notes    && node tools/check.mjs
cd ~/Developer/rux-scheduler   && node tools/check.mjs
cd ~/Developer/rux-sm.github.io && node tools/check.mjs

    The hub's and the scheduler's checks need no install: each reads its own vendor/. it reads its own vendor/. rux-backend is not checked here — see page 1.

  5. Create the VS Code workspace that holds all six, so one window pulls and shows everything.

    cp ~/Developer/rux-ds/docs/rux.code-workspace ~/Developer/
code ~/Developer/rux.code-workspace

    The file lives in rux-ds under docs/ and is copied up because VS Code wants it beside the six folders; edit the copy in rux-ds, never the one in ~/Developer — that one is overwritten by the next run of this step, so a fix made there is lost on the other Mac. A new app joins here and in the pull loops above, in the same commit that adds it to the hub's switcher.json. Auto-fetch keeps the ahead/behind arrows honest without pulling; pull-tags brings rux-ds's version tags down; rebase-when-sync puts your commits on top of the other Mac's instead of making merge commits. Scan depth 0 stops VS Code listing carbon-website/, IBM's docs clone that rux-ds keeps gitignored as a quarry; it is not yours and never needs syncing, and no Mac needs it: nothing in npm run verify reads it, and a Mac that wants it clones github.com/carbon-design-system/carbon-website into rux-ds/, where .gitignore already hides it. Always open VS Code from this file — the window title ends in “(Workspace)” — and in the Source Control view each repo gets its own row. Pull from there or with the loop on page 1; what matters is all six, before any agent starts. An up-arrow on a row at the end of a session is a commit only this Mac has.

  6. Prove the hooks work in all six repositories. This tries to make an empty commit with a forbidden trailer; each hook must refuse it. A refusal changes nothing. If one is accepted, do not push it: run the safe undo command below in that repository, then repeat step 3 for it. This is the only step that proves git actually calls the hook, rather than that the script exists or the setting is spelled right — running the script by hand proves neither. rux-backend had no hook at all until 2026-09-04 and nothing said so.

    for r in rux-ds rux-ln-atlas rux-ln-notes rux-scheduler rux-sm.github.io rux-backend; do
  git -C ~/Developer/$r commit --allow-empty -m "test: Probe

Co-Authored-By: nobody"; done
# expect six refusals: commit-msg: Co-Authored-By trailer …

# ONLY if a probe was accepted, run this inside that repository:
git reset --soft HEAD~1

    --soft removes only the unpushed probe commit and leaves files alone. Do not use reset --hard; it can erase real work.

Reference

The six repos

What each one is, how to run it, where to edit, how to verify and how it is released — one table, kept in one place: the workspace page in rux's config (~/claude-config/workspaces/rux-ln.md, private). This card used to carry a copy of that table; it went stale, so it now carries the pointer. The checks are in step 2 of the loop above.

Atlas never touches rux-ds. The content line is atlas → notes ← rux-ds; rux-ds also feeds the hub and the scheduler, and the hub feeds every app its list by URL.
rux-ui is outside the family but no longer separate. rux-backend adopted its Supabase project rather than provision a second, so one database holds two systems: public is rux-ui's and is never edited here, platform is ours. Its public.profiles is a driver roster, unrelated to platform.profiles. The scheduler reads rux-ui's tables live — buses, trips, drivers — so rux-ui's own pages are still how that data is entered.
Only rux-sm.github.io can carry that name. Rename it and /switcher.json and /switcher.js 404 on every module — silently, each page falling back to the entries it shipped.
