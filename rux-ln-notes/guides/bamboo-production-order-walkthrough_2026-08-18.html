Bamboo Production Order Walkthrough — Review

Draft Review Updated 2026-09-03

Read the summary

Objective

Continue the bamboo test-item training case (BAM-ROD, BAM-SLEEVE, BAM-CHOP-PAIR) past master-data creation: build a job shop bill of material and routing, calculate a standard cost, source component stock by purchasing and receiving, and run the resulting production order through to a finished-goods receipt. This is the walk SG-create-basic-test-items-and-defaults.md phases 6–10 and SG-manual-production-order-existing-master-data.md phases 3–5 had been waiting on.

Key topics discussed

3.1 Job shop bill of material

The trainee built Job Shop Bill of Material tibom3600m000 JB0000242 revision 000001 for BAM-CHOP-PAIR — BOM Quantity 1 ea, source Manual — with two material lines from Job Shop List of Materials tibom3110m000: BAM-ROD and BAM-SLEEVE, warehouse ADNA02.

Note

Later in the session a second revision, `000002`, was created as a deliberate teaching demonstration of the revision mechanism — see section 3.6.

3.2 Job shop routing

Job Shop Routing tirou4600m000 0 revision 000001, Routing Quantity 1 ea, one operation: Operation 10, Reference Operation A1004 ("Cutting - shear"), Work Center A1000, Machine Type AA1005. This is an independent, unambiguous capture of the operation grid's column order (Operation → Reference Operation → Work Center → Machine Type). It settles a long-open question about whether an earlier (2026-08-06) frame had work center and reference operation transposed.

3.3 Standard cost calculation

The consultant located the standard-cost calculation route the library had been missing: it is not a separate session but an Actions command on Item tcibd0501m100 itself — Calculate and Actualize Standard Costs... — run against BAM-CHOP-PAIR's Enterprise Unit row (4201AA, Legal Entity US - A). Narration confirms this is run at the line level after the item exists, and that an item without an actualization date is not yet costed.

3.4 Component stock via purchase and receipt

Route A (purchase) was walked in full, not just proposed:

  1. Purchase Order Intake Workbench tdpur4601m200 → Purchase Order tdpur4100m900, order 100000677.
  2. Buy-from business partner `BP4000007` VISTA MACHINES INC., selected from the standard test-partner list via the Buy-from Business Partners lookup (tccom4520m000). Order Type IPO, Purchase Office 401P00.
  3. Order lines booked exactly from the BOM: BAM-ROD qty 2.0000 ea, BAM-SLEEVE qty 1.0000 ea, both to ADNA02 RAW MATERIALS.
  4. The order generated a Warehousing Order whinh2100m100, type PUI "Purchase Receipts". Actions ➔ Receive... opened Warehouse Receipt whinh3512m000, receipt 100001505.
  5. Receiving hit a real error, whinh0032 — "Advise and put away receipt line: 100001505 - 10 Receipt Line Stock Point Details not found," plus 3 more messages. The receipt nonetheless reached Confirmed, All Lines Final and Complete, packing slips 123/124. How the error was cleared was not captured.

3.5 Production order — release through finished-goods receipt

Production order 010000749 for BAM-CHOP-PAIR (BOM JB0000242 rev 000001, routing 0 rev 000001) ran Created → Released → material issue → Production Completed as one continuous session — the first time those phases have been walked end to end on one order. Several step-level values (the exact Completed quantity, whether tisfc0120s000 opened, the finished-item on-hand read) were not captured cleanly.

3.6 Warehouse inspection, order closure, and the revision demonstration

A Warehouse Inspection whinh3122m000 ran against the finished BAM-CHOP-PAIR at ADNA01, Inspection Status Open at the point captured. Narration states plainly that Close Order was blocked until this inspection's put-away step finished — "if your status on that order isn't set to put away, and all of your materials are not issued, it's not going to let you close out that order" — and that closing requires both materials issued and the end item not just received but put away. This is narration (TR-grade), not yet confirmed against ticst0201m000's own help, which was previously read as silent on any precondition.

Close Production Orders was actually run in this session, despite being explicitly out of scope for both Scenario Guides. Recorded here as observed environment behavior; it does not change either guide's documented scope boundary.

Separately, the consultant walked the trainee through a BOM revision demonstration: created JB0000242 revision 000002 (quantity 2), approved it, flagged it Use for Planning and Use for Costing, then selected the original revision 000001 and ran Actions ➔ Expire Revision — explaining that LN will now select 000002 because 000001 is no longer valid.

Decisions made

  1. Route A (purchase) is the procedure for stocking training-item components, not Route B (adjustment) — the consultant walked the trainee through the full purchase-to-receipt cycle rather than a stock adjustment.
  2. `BP4000007` VISTA MACHINES INC. is the standing test business partner for this kind of purchase, selected from the existing test-partner list rather than creating a new one.
  3. Close Production Orders stays out of the two Scenario Guides' documented scope, even though it was run in this session — the guides continue to end at finished-goods receipt.

Methodology and process notes

  • A grid's column order is a session property, not a per-record one. Once one unambiguous capture of tirou4600m000's operation grid confirmed Operation → Reference Operation → Work Center → Machine Type, that column order could be safely applied to re-read an earlier, differently-worded capture of the same session (the 2026-08-06 frame) — this is how that question closed from a second, unrelated recording rather than needing the original frame re-shot.
  • Narration can answer a question official help left silent on, but it stays TR-grade until sourced. The Close Order put-away precondition is a specific, mechanistically plausible claim, not a vague impression — but it was still logged as a narrowing lead, not written into a guide as a confirmed rule.
  • Deliberately running a "wrong" or out-of-scope action during training is itself worth recording. Running Close Production Orders here, and creating-then-expiring a second BOM revision, were both teaching choices, not procedure — the review records them as what happened without pulling them into either Scenario Guide's scope.
  • Recording: the source on file — the raw video stays local and never commits; the manifest carries its checksum and lists the transcript derivatives.
